# The `dnd` MCP server (`apps/mcp`)

A local stdio MCP server (`dnd` in `.mcp.json`, package `dnd-mcp`) that lets an AI agent (Claude Code) work with the app as the token's owner: search, read, create and edit characters, NPCs, monsters, items, abilities and effects and the links between them, upload their images from disk, and read and build maps. Deleting and publishing stay with the user in the UI. Image generation is the separate `comfy` server ([plan/ai-access.md](plan/ai-access.md)). It is a thin client over the REST API, authenticated with an API token (what a token may do on the server: [server.md](server.md), «API tokens»), so every rule (operation parsing, limits, ownership, undo) lives on the server and is the same for the GM's UI and for the agent. Design notes: [plan/map.md](plan/map.md).

## Tools

| Tool                                     | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search`                                 | Start here. Own characters and NPCs, own and published monsters, items, abilities and effects; `kind` narrows to one kind, `q` is a part of the name (case-insensitive, «ё» = «е»). Each row: id, kind, name, `category`, `own` (else `author`), `visibility` (`hidden`, `public`, or `link` for a character shared by link), `hasImage`. At most 50 rows plus `total` and `byKind` (the count per kind, since the cut follows the kind order). The server lists have no name filter, so the tool fetches the lists (both `scope=mine` and `scope=catalog`) and filters itself.                            |
| `get`                                    | One whole record by `kind` and id, as `GET /api/<kind>/:id` returns it: a character or NPC with its inventory, abilities and effects; a monster with its abilities, gear and effects; an item, ability or effect.                                                                                                                                                                                                                                                                                                                                                                                          |
| `format_guide`                           | The fields of one kind for `create` and `update`: what is required, the allowed values and ready samples. The values come from `shared` constants and labels, the samples from shared defaults or values typed against shared types; each field description is keyed by the shared type (`satisfies Record<keyof MonsterStatBlock, string>` and so on), so a new field or kind without a line breaks the build (`src/formatGuide/`). Repeats the rules: stat blocks and spells from the 2024 books, homebrew marked as such.                                                                               |
| `create`                                 | `POST /api/<kind>`. Fills `isPublic: false`, an empty description and sources for a catalog record, and the character `kind` (`pc`/`npc`) from the tool's kind. `isPublic: true` gets the server's 403.                                                                                                                                                                                                                                                                                                                                                                                                    |
| `update`                                 | Read, merge, `PUT`: the patch holds only what changes; nested objects merge, arrays and `details` are replaced whole (a category change must not keep the old `details` keys). Before merging, the record is turned back into a request body: pack contents keep only `itemId` and `quantity`, effects in ability steps only `effectId` (`src/recordInput.ts`); the other read-only fields are dropped by the server's `whitelist`.                                                                                                                                                                        |
| `link_add`, `link_update`, `link_remove` | Items, abilities and effects on a character, NPC or monster (`/api/characters/:id/items` and so on). Each link takes only its own fields (an item on a character: `quantity`, `location`, `unpack`; an ability on a monster: `perDay`; …); another field is an error here, since the server would drop it silently. `entryId` is the row id from `get`, not the catalog id.                                                                                                                                                                                                                                |
| `upload_image`                           | An image from disk (absolute `path`, PNG, JPEG or WebP by its first bytes, up to 10 MB) as `multipart`: a catalog record's single image is replaced (`PUT /api/<kind>/:id/image`), a character's or NPC's is added to the gallery (`POST /api/characters/:id/images`), `main: true` makes it the main one. The thumbnail is the server's default unless `thumb` gives a square as fractions of the image (centre and side), since the server shrinks the image to 2048 px and the model can't know the pixel size in advance.                                                                              |
| `list_maps`, `create_map`                | Map records of the token owner; the list gives each map's `startCount`. `create_map` takes an optional `width` × `depth` (default 32 × 32).                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `block_guide`                            | Coordinates and compass directions, the map size, block names, materials, shapes, rotation, operation formats (including `resize`) and map objects (kinds, footprints, facing, the object ops). Built from `shared`, so it can't drift from what the server accepts. Read it before the first edit.                                                                                                                                                                                                                                                                                                        |
| `map_summary`                            | The map size and height limit, the bounds of what is built, block counts, palette, and the map objects: id, kind, cell, label, facing, size and warnings (can't stand there, in the air, past the border, a deleted catalog link).                                                                                                                                                                                                                                                                                                                                                                         |
| `map_slice`                              | ASCII slice at height `y` (rows = z with north up, columns = x, legend). Optional rectangle (default: the whole map), max 100 000 cells. Objects standing on that level are listed under the grid.                                                                                                                                                                                                                                                                                                                                                                                                         |
| `map_section`                            | ASCII vertical section through the plane `x = at` or `z = at` (rows = height, top up; `axis: z` looks from the south, `axis: x` from the west). Checks roofs, storey heights, stairs and the openings above them, which a horizontal slice can't show. Optional ranges, max 100 000 cells.                                                                                                                                                                                                                                                                                                                 |
| `apply_ops`                              | A batch of up to 100 operations: all-or-nothing, one undo unit. `resize` changes the map size by side and shifts the blocks when it grows west, north or down ([plan/map-editor.md](plan/done/map-editor.md)); later ops in the same batch use the new coordinates. Map objects (start points, monsters, NPCs, containers, items on the floor; [plan/done/map-objects.md](plan/done/map-objects.md)) are ops too: `placeObject`, `moveObject`, `turnObject`, `updateObject`, `removeObject`; the result's `createdObjectIds` gives the new objects' ids, since a batch can't refer to an object it places. |
| `undo`, `redo`                           | The map's journal stack. Edit tools drop `changes` (the per-cell changeset) and `refs` (names and images of linked catalog entries) from the result: they are for the web and would flood the model's context.                                                                                                                                                                                                                                                                                                                                                                                             |
| `find_catalog`                           | Search what can be placed on a map: `kind` `monster` (own and published, with size and role — a `unique` one only once per map), `item` (own and published) or `npc` (own), `q` a part of the name; 20 at most. The ids go into `placeObject`.                                                                                                                                                                                                                                                                                                                                                             |
| `view_url`                               | A link to the 3D view with a camera (`view=top\|north\|south\|west\|east`, or exact `cam`/`target`) and a height cut `y`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

API errors come back as tool results with `isError` and the server's Russian message, not as protocol errors, so the model sees what to fix ("Операция №2: Неизвестный блок…").

## The build → look → fix loop

1. Edit with `apply_ops`, check with `map_slice` (plan), `map_section` (heights) and `map_summary`.
2. `view_url` → open it with the browser MCP → **wait for the text «Сцена готова»** (the page shows it after the first frame rendered with the object thumbnails loaded or failed; before that the canvas may still be empty or the cards blank) → screenshot. Make these three calls one after another, not in parallel: a parallel screenshot is taken before the wait finishes and shows the loader.
3. Same URL, same picture: the camera comes from the URL, not from mouse drags.

Building proportions (a storey is 3 blocks, a door 2, creature heights) are decided in [plan/map.md](plan/map.md), «Два масштаба: правила и пропорции»; `block_guide` repeats them for the model.

**The browser must be logged in as the token's owner.** The map page uses the browser's cookie session, not the API token. If the browser MCP profile is logged in as someone else, `view_url` shows «Карта не найдена» — log in as the right user in that browser window. Putting the token in the URL is deliberately not an option: it would leak into history and logs.

## Connecting

1. Build: `pnpm --filter shared build && pnpm --filter dnd-mcp build` (`.mcp.json` runs `apps/mcp/dist/index.js`).
2. Create a token in the UI: «Профиль» → «Токены для нейросети» (`/profile`; the old `/tokens` redirects there). It's shown once.
3. Copy `apps/mcp/.env.example` to `apps/mcp/.env` (gitignored) and paste the token into `DND_API_TOKEN`. The server reads this file itself on start (`src/envFile.ts`); real process environment variables win over it. `.mcp.json` holds no settings, so nothing secret can end up in git.
4. Optional in the same file: `DND_API_URL` (default `http://localhost:3000/api`) and `DND_WEB_URL` (default `http://localhost:5173`). For production use `https://dnd.aoshi.ru/api` and `https://dnd.aoshi.ru`.
5. Restart Claude Code and approve the project MCP server `dnd` (until 2026-10-20 it was `dnd-map`; drop the old one from `enabledMcpjsonServers` in `.claude/settings.local.json` if it is still there).
6. Log in to the site in the browser MCP's window as the same user (see the loop above).

Without a token the server still starts; every tool then explains where to get one.

stdout is the protocol channel: the server logs only to stderr.
