# The `dnd` MCP server (`apps/mcp`)

A local stdio MCP server (`dnd` in `.mcp.json`, package `dnd-mcp`) that lets an AI agent (Claude Code) work with the app as the token's owner: search, read, create and edit characters, NPCs, monsters, items, abilities, effects, block groups (own blocks for maps), voxel models and furniture (an own model with a mount, placed on maps) and the links between them, upload their images from disk, and read and build maps. Deleting and publishing stay with the user in the UI. Image generation is the separate `comfy` server ([plan/ai-access.md](plan/ai-access.md)). It is a thin client over the REST API, authenticated with an API token (what a token may do on the server: [server.md](server.md), «API tokens»), so every rule (operation parsing, limits, ownership, undo) lives on the server and is the same for the GM's UI and for the agent. Design notes: [plan/map.md](plan/map.md).

## Tools

| `search`                                       | Start here. Own characters and NPCs, own and published monsters, items, abilities, effects, block groups (`block_group`), voxel models (`voxel_model`) and furniture (`furniture`); `kind` narrows to one kind, `q` is a part of the name (case-insensitive, «ё» = «е»). At most 50 rows plus `total` and `byKind` (the count per kind, since the cut follows the kind order). The server lists have no name filter, so the tool fetches the lists (both `scope=mine` and `scope=catalog`) and filters itself.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

| `format_guide`                                 | The fields of one kind for `create` and `update`: what is required, the allowed values and ready samples. | `update`                                       | Read, merge, `PUT`: the patch holds only what changes; nested objects merge, arrays, `details` and a model's `cells` are replaced whole (a category change must not keep the old `details` keys, and a merged `cells` could never lose a cell). The answer is the link list in short (`src/linkSummary.ts`): the row id, its own fields and the linked record's id and name, since the server nests the whole record in every row; the record itself comes from `get`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `equip_item`, `unequip_item`, `set_attunement` | The doll of a character or NPC (`PUT`/`DELETE /api/characters/:id/equipment/:slot`, `/items/:entryId/attunement`; rules in [dnd/weapons-armor.md](dnd/weapons-armor.md#кукла-места-и-настройка)): put an inventory row on a slot (`EQUIP_SLOTS`), take a slot off, attune or end it. The item card in `get` carries `equip.slots`, where it fits. The thumbnail is the server's default unless `thumb` gives a square as fractions of the image (centre and side), since the server shrinks the image to 2048 px and the model can't know the pixel size in advance.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## The build → look → fix loop

1. Edit with `apply_ops`, check with `map_slice` (plan), `map_section` (heights) and `map_summary`.
2. `view_url` → open it with the browser MCP → **wait for the text «Сцена готова»** (the page shows it after the first frame rendered with the object thumbnails loaded or failed; before that the canvas may still be empty or the cards blank) → screenshot. Make these three calls one after another, not in parallel: a parallel screenshot is taken before the wait finishes and shows the loader.
3. Same URL, same picture: the camera comes from the URL, not from mouse drags.

Building proportions (a storey is 3 blocks, a door 2, creature heights) are decided in [plan/map.md](plan/map.md), «Два масштаба: правила и пропорции»; `block_guide` repeats them for the model.

**The browser must be logged in as the token's owner.** The map page uses the browser's cookie session, not the API token. If the browser MCP profile is logged in as someone else, `view_url` shows «Карта не найдена» — log in as the right user in that browser window. Putting the token in the URL is deliberately not an option: it would leak into history and logs.

## Connecting

1. Build: `pnpm --filter shared build && pnpm --filter dnd-mcp build` (`.mcp.json` runs `apps/mcp/dist/index.js`).
2. Create a token in the UI: «Профиль» → «Токены для нейросети» (`/profile`; the old `/tokens` redirects there). It's shown once.
3. Copy `apps/mcp/.env.example` to `apps/mcp/.env` (gitignored) and paste the token into `DND_API_TOKEN`. The server reads this file itself on start (`src/envFile.ts`); real process environment variables win over it. `.mcp.json` holds no settings, so nothing secret can end up in git.
4. Optional in the same file: `DND_API_URL` (default `http://localhost:3000/api`) and `DND_WEB_URL` (default `http://localhost:5173`). For production use `https://dnd.aoshi.ru/api` and `https://dnd.aoshi.ru`.
5. Restart Claude Code and approve the project MCP server `dnd` (until 2026-10-20 it was `dnd-map`; drop the old one from `enabledMcpjsonServers` in `.claude/settings.local.json` if it is still there).
6. Log in to the site in the browser MCP's window as the same user (see the loop above).

Without a token the server still starts; every tool then explains where to get one.

stdout is the protocol channel: the server logs only to stderr.

# The `comfy` MCP server (`apps/comfy-mcp`)

A second local stdio MCP server (`comfy` in `.mcp.json`, package `comfy-mcp`) that only generates images on ComfyUI and knows nothing about DnD. ComfyUI runs on another computer with the GPU (RTX 5070 Ti), reached over Radmin VPN; if it is off, `comfy` answers with a clear error and `dnd` works as usual. Plan and decisions: [plan/ai-access.md](plan/ai-access.md).

## Tools

| Tool           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `comfy_status` | Whether ComfyUI answers (`/system_stats`, `/queue`), its GPU and VRAM, the queue, the checkpoints, LoRAs and upscale models it has (`/models/checkpoints`, `/models/loras`, `/models/upscale_models`), and the style presets, each with `missing` — the preset's files ComfyUI doesn't have. The presets are listed even when ComfyUI is down.                                                                                                                                                                                |
| `generate`     | `style`, `prompt` (only the subject, in English), optional `negative`, `seed`, `width`, `height` and `count` (up to 4). Builds the preset's graph, queues it (`POST /prompt`), polls `/history/{id}` every second up to `COMFY_TIMEOUT_SEC`, downloads the images (`/view`) and saves them as PNG to `COMFY_OUTPUT_DIR`. The result is the file paths, the seed and a 512 px JPEG preview of each image, which the model looks at. A path goes on to `dnd`'s `upload_image`: the image itself never passes through the model. |

ComfyUI errors come back as tool results with `isError`: unreachable (the real cause, a 30 s limit per request), a graph rejected by ComfyUI (the node and its message, such as a missing checkpoint), a failed run (`execution_error`, such as CUDA out of memory), a timeout.

## Style presets

One file per style in `apps/comfy-mcp/styles/<name>.json` (in git), checked by `src/styles.ts` and read on every call, so editing one needs no restart: the graph (`workflow`, so far `txt2img` for single-checkpoint models such as SD 1.5 and SDXL, built in `src/workflow.ts`), `checkpoint`, `loras`, `sampler`, `scheduler`, `steps`, `cfg`, the default `width` and `height`, `promptPrefix`, `promptSuffix` and `negative` around the model's subject, and an optional `upscale` (`src/upscale.ts`).

`upscale` runs after the first pass, because SDXL draws cleanly only near 1024 px and duplicates anatomy above that: an upscale model (`model`, such as `4x-UltraSharp.pth`) enlarges the image, which is then scaled to `width · scale` × `height · scale`. With `denoise` it is a hires fix: the checkpoint redraws the enlarged image in a second pass with the same seed, prompt and LoRAs (`steps` of its own if given), which adds real fine detail; without `denoise` it is the upscale model alone, sharper edges but nothing new.

Two presets ship, both on MoonArt Cauldron Mix (`MoonartCauldronMix_sdxlV10.safetensors`, [civitai](https://civitai.com/models/1741447/moonart-cauldron-mix)) with Euler a, 30 steps, CFG 5 and a hires fix ×1.5 at denoise 0.35 through `4x-UltraSharp.pth` (~28 s an image on the RTX 5070 Ti, a 2–3 MB PNG):

- `dark-fantasy-creature` — creatures, monsters, characters and NPCs: one figure in the centre, 832 × 1216 → 1248 × 1824.
- `dark-fantasy-item` — weapons, potions, scrolls, treasure: one object in the centre with a soft glow, 1024 × 1024 → 1536 × 1536.

The look is a D&D-style fantasy illustration on a plain gradient background with a vignette, with no scene behind, so a card or a 256 px thumbnail reads at a glance. The names say «dark fantasy» because that was the first brief; they were kept so the plan and earlier notes stay valid.

### Why these models (stage 6 of the plan, 2026-10-21)

Every candidate drew the same subjects with the same seed (a rat, a potion, an NPC portrait, a sword, then a goblin, an elf archmage, a potion and a scroll):

- **MoonArt Cauldron Mix** — picked for both presets. It follows the subject (a goblin is a goblin, a scroll is a scroll), keeps the plain background, and creatures and items come out in one style. Its author's settings ([civitai](https://civitai.com/models/1741447/moonart-cauldron-mix)): quality tags `masterpiece, best quality, very aesthetic, 4k` and `worst quality` in the negative, 832 × 1216 or 1024 × 1024, Euler a or DPM++ 2M Karras, CFG 5–7, 28–35 steps. Euler a, unlike DPM++ 2M, also stopped the stray gems, corks and rings around items.
- **ZavyChromaXL** draws creatures almost the same as MoonArt; with the **Zavy's Fantasy Icons** LoRA (trigger `zavy-fntscn`, strength 0.5–0.9) its items are clean icons, but MoonArt with Euler a got close without a second model.
- **FantasyPrime 2.5D** — rich but ignores the plain background and swaps the subject (a jar for a bottle, a case for a scroll), anime-leaning faces.
- **Juggernaut XL Ragnarok** with the Dark Grim Fantasy and Textured Painterly LoRAs — the grimmest look, but clutter and lettering on items and missing clothes on people.
- **Fantastic Characters SDXL**, **DreamShaper XL alpha2** — nothing over MoonArt; DreamShaper puts a scene behind and mixes up props.
- **novaAnimeXL / novaFurryXL** (Illustrious) — even and clean but anime; **cyberrealisticPony** — photoreal, turns monsters into people.

Upscaling was compared on the same images: the upscale model alone ×2 (2048 px, ~13 s) is sharper but plasticky; the hires fix ×1.5 (1536 px, ~28 s) and ×2 (2048 px, ~45 s) add fur, skin and engraving detail, and ×1.5 was chosen for speed, since the site shows images far smaller. The denoise follows the usual advice for a pixel-space second pass after an upscale model, 0.25–0.5 and nearer the low end ([cubiq/ComfyUI_Workflows](https://github.com/cubiq/ComfyUI_Workflows/blob/main/upscale/README.md)); if faces drift, lower it first.

## The generate → look → upload loop

1. `comfy_status`, then `generate` with a short subject.
2. Look at the preview against the description; fix the prompt or the seed. At most three tries per image, then show the user the best ones and ask. Small defects (fingers, lettering) may go unnoticed on the preview.
3. `dnd`'s `upload_image` with the chosen path.

## Connecting

1. Build: `pnpm --filter comfy-mcp build` (`.mcp.json` runs `apps/comfy-mcp/dist/index.js`).
2. On the GPU computer: start ComfyUI with `--listen` (port 8188) and open the port in the firewall for the Radmin network.
3. Copy `apps/comfy-mcp/.env.example` to `apps/comfy-mcp/.env` (gitignored) and set `COMFY_URL` to that computer's Radmin address, such as `http://26.x.x.x:8188`. Real environment variables win over the file. Optional: `COMFY_OUTPUT_DIR` (default `apps/comfy-mcp/output/`, gitignored) and `COMFY_TIMEOUT_SEC` (default 300; the first load of a model is slow).
4. Restart Claude Code and approve the project MCP server `comfy`.

Without `COMFY_URL` the server still starts; `generate` then explains where to set it. Like `dnd`, it logs only to stderr.
