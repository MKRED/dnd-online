# Редактор карт: объекты на карте

Подробный план второй половины блока 3 из [roadmap.md](../roadmap.md): точки старта персонажей, существа (монстры и НПС), контейнеры с предметами, предметы на полу и направление взгляда. Первая половина — [map-editor.md](map-editor.md).

Составлен 2026-10-20 вместе с пользователем. Код карты — `packages/shared/src/map/`, сервер — `apps/server/src/maps/`, редактор — `apps/web/src/features/maps/`, MCP — `apps/mcp/`.

## Что есть сейчас

Проверено по коду 2026-10-20.

- **Карта — только блоки.** Изменения идут операциями `MapOp` (`setBlock`, `fillBox`, `hollowBox`, `replace`, `resize`) через `editMap` в `shared`. Каждая пачка — запись журнала `map_ops` с changeset (клетки «до» и «после», дописанная палитра, размер до и после у `resize`). Отмена и возврат — `applyChangeset` со своими конфликтами по клеткам.
- **Объектов нет нигде.** В [map.md](../map.md) («Модель данных») записано: «токены, двери-объекты, источники света, сундуки — свои таблицы с координатами клеток». В roadmap решено: объекты — операции того же журнала. Ниже — как это совмещается.
- **Фигурка «Хода»** (`walkTest/`) — единственное, что сейчас стоит на карте, кроме блоков. Её не сохраняют, но правила стойки (`standHeight`) и тело существа по размеру (`rules/creature.ts`) уже есть в `shared`.
- **Размер существа** есть только у монстра (`MonsterStatBlock.size`). У персонажа его нет: размер вида не записывается ([dnd/species.md](../../dnd/species.md)).
- **Роль монстра** — обычный или уникальный (`MONSTER_ROLES`). Проверять «уникальный на сцене только один» должны редактор и сцена (комментарий в `shared/src/monsters.ts`).
- **API-токен** открывает только карты ([map.md](../map.md), этап 4). Через MCP монстров и предметы сейчас не найти.

## Решения

### Объекты — операции журнала, хранение — своя таблица

Решено без вопроса: так сходятся [map.md](../map.md) и roadmap.

- **Хранение** — таблица `map_objects`: карта, номер объекта, вид, клетка, взгляд, признак «скрыт» и поля вида в jsonb. Это «своя таблица» из `map.md`.
- **Менять объекты можно только операциями.** Отдельного CRUD нет: операция объекта идёт через `editMap` и пишет запись журнала, как блоки. Так у объектов сразу есть отмена и повтор, а пачка блоков и объектов — одна единица отмены («построил комнату и поставил в неё сундук» отменяется разом). Нейросеть ставит объекты тем же `apply_ops`.
- **Номер объекта** — целое число внутри карты, его выдаёт сервер из счётчика в строке карты. Номера не переиспользуются, как id палитры. Иначе отмена удаления старого объекта воскресила бы его под номером, который уже занял новый. Короткий номер удобнее uuid для нейросети («сдвинь объект 7»).
- **Номера новых объектов возвращаются в ответе правки** по порядку операций. Сослаться на объект, созданный в той же пачке, нельзя: нейросеть сначала ставит, потом правит. Решено без вопроса: ссылки внутри пачки усложнили бы разбор, а нейросети хватит двух вызовов.

### Операции объектов

```ts
{ op: 'placeObject', at: [x, y, z], object: { kind: 'start', facing?: 0..315 } }
{ op: 'placeObject', at, object: { kind: 'monster', monsterId, facing? } }
{ op: 'placeObject', at, object: { kind: 'npc', characterId, size?, facing? } }
{ op: 'placeObject', at, object: { kind: 'container', name?, look?, items?: [{ itemId, quantity }] } }
{ op: 'placeObject', at, object: { kind: 'item', itemId, quantity? } }
{ op: 'moveObject',   id: 7, at: [x, y, z] }
{ op: 'turnObject',   id: 7, facing: 90 }
{ op: 'updateObject', id: 7, object: { … } }   // содержимое контейнера, количество, размер НПС
{ op: 'removeObject', id: 7 }
```

Так операции устроены в коде (этап 1). «Существо» редактора — два вида, `monster` и `npc`: у них разные ссылки, а размер есть только у НПС. Общее у всех видов:

- `at` — клетка, где стоят ноги (уровень, как у фигурки «Хода»). У существа больше Среднего это северо-западная клетка его места: место занимает квадрат по размеру (`rules/creature.ts`).
- `facing` — у старта и существа. У контейнера и предмета взгляда нет.
- `hidden` — признак «видит только мастер». Сейчас он всегда `false`, им ничего не пользуется. Поле заложено сразу (roadmap, «После первой партии»: засада, спрятанный сундук).

**Виды объектов:**

- **Старт** — точка, куда встанет персонаж игрока. Без привязки к персонажу: кто где встанет, решит лобби. Точки нумеруются по порядку на карте: ①, ②, ③. Решено без вопроса: игроков в карте ещё нет, привязать не к чему.
- **Существо** — монстр из каталога или НПС (персонаж с типом НПС). Размер монстра берётся из его стат-блока. У НПС размера нет, поэтому он лежит на объекте: по умолчанию Средний, мастер меняет в свойствах. Обычных монстров одного вида можно ставить сколько угодно.
- **Контейнер** — сундук, ящик, бочка, мешок. У него своё название, вид (из короткого списка, только для картинки) и содержимое — предметы каталога с количеством. Ссылки на каталожный предмет категории «Контейнер» нет. Почему: сундук на карте — место для добычи, а не вещь, которую берут с собой. Связать их можно потом.
- **Предмет на полу** — предмет каталога с количеством.

### Ссылки на каталог

- **Ссылка, а не копия**, как в инвентаре и у монстров. Внешних ключей нет: ссылки лежат в jsonb объекта, и отмена может вернуть ссылку на то, что уже удалили. Поэтому удалённое и скрытое разрешаются при чтении:
  - скрытый автором монстр или предмет — заглушка «Скрыт автором»;
  - удалённый — заглушка «Монстр удалён» или «Предмет удалён». Объект остаётся на карте, мастер может убрать или заменить его.

  Решено без вопроса: так же ведут себя закладки ([bookmarks.md](bookmarks.md)).

- **Что можно поставить.** Монстры и предметы — свои или опубликованные. НПС — только свои. Сервер проверяет это при `placeObject` и `updateObject` (400 «Монстр не найден»). Ссылки, которые уже на карте, повторно не проверяются. Отмена и возврат ссылки тоже не проверяют: их изменения уже были на карте, как и с границей для блоков.
- **Уникальный монстр на карте только один.** Сервер отклоняет вторую постановку с 400: «Уникальный монстр «Дракон» уже стоит на карте (объект 4)». Решено без вопроса: roadmap требует проверки в редакторе. Чтобы `editMap` оставался чистой функцией, сервер до применения читает роли и размеры монстров из пачки и передаёт их справочником. То же при `updateObject`, который меняет существо на уникального монстра. Отмена и возврат не проверяют: «поставил, убрал, поставил другого, отменил удаление» вернёт второго. Если монстра сделали уникальным, когда на карте уже стоят двое, редактор их тоже не трогает. Оба случая ловит сцена при запуске.
- **Чтение.** Объекты приходят в ответе `/chunks` вместе с блоками и размером одним снимком. Рядом — справочник ссылок: имя, миниатюра и размер для существ, имя и миниатюра для предметов, или заглушка.

### Журнал, отмена, размер карты

- **Changeset несёт объекты**: номер, объект «до» и «после» (`null` — не было или удалён), рядом с клетками и размером. Отмена и возврат идут через тот же `applyChangeset`. Конфликт — как у клеток: если объект после операции изменили, отмена его не трогает и считает конфликтом.
- **`resize` двигает объекты вместе с блоками.** Рост на запад, север и вниз сдвигает их на тот же шаг. Срезанные объекты ведут себя как блоки:
  - с запада, севера и снизу удаляются всегда;
  - с востока и юга удаляются или остаются за границей и не рисуются, по `cut`. Признак `hidden` им не ставится: он значит «видит только мастер», а это другое.

  `resizeLoss` и диалог размера считают объекты отдельной строкой: «пропадут 12 блоков и 2 объекта». Это нужно в любом случае, иначе гоблин после сужения стоял бы за границей.

- **Объекты не мешают блокам.** Блок можно поставить в клетку объекта, операции блоков объекты не проверяют. Редактор подсвечивает существо или старт красным, если там нельзя стоять (`standHeight`, как фигурка «Хода»). Сводка для нейросети пишет «объект 7 в стене». Решено без вопроса: запрет ломал бы заливку и `resize`, а «стоит ли тут существо» — вопрос правил, а не модели.
- **Лимит** — `MAP_MAX_OBJECTS` в конфиге сервера, по умолчанию 500 на карту.

### Направление взгляда

- 8 направлений: 0, 45, …, 315 градусов по часовой стрелке от севера. Это отдельный тип, а не `Rotation` блоков: у блока 4 поворота и они лежат в битах клетки.
- Правило дома: в правилах 2024 направления взгляда нет (roadmap). Пока оно только для наглядности. Перед кодом этапа 1 проверяем по DMG 2024, есть ли там необязательное правило о направлении. Записываем в `docs/dnd/facing.md` как отступление от книги — тем же коммитом.

### Редактор: один инструмент «Объекты»

Выбрано пользователем 2026-10-20.

```
┌─┬──────── сцена ──────────────┬──────────────────┐
│▣│ ↶ ↷              Центр y=1 ▲▼│ Объекты          │
│✎│                              │ Ставить:         │
│⌫│     ⛀   ①  ②                │ (•) Старт        │
│▦│        ▓▓▓                   │ ( ) Существо     │
│□│     👹                       │ ( ) Контейнер    │
│⇄│                              │ ( ) Предмет      │
│👣│                              │ Взгляд (R): ↗    │
│◈│ x 12 · y 1 · z 7             │──────────────────│
└─┴──────────────────────────────┤ На карте:        │
                                 │ ① ② Старт        │
                                 │ 👹 Гоблин  #4 ◀  │
                                 │ ⛀ Сундук   #5    │
                                 └──────────────────┘
```

- **Инструмент «Объекты»** — восьмой в полосе, клавиша 8. Справа — что ставить: старт, существо (поиск по монстрам и своим НПС), контейнер или предмет (поиск по каталогу). Клик по клетке ставит объект.
- **Правка — кликом и перетаскиванием** (выбрано пользователем 2026-10-20):
  - клик по объекту выделяет его. Справа — его свойства: взгляд стрелками из 8 направлений, размер у НПС, содержимое контейнера, количество у предмета, «Удалить (Del)»;
  - перетаскивание переносит объект в другую клетку: одна операция `moveObject` при отпускании. ЛКМ сейчас двигает камеру (`MapControls`), поэтому нажатие на объект выключает камеру до отпускания, а перетаскивание в другом месте двигает её, как раньше;
  - R поворачивает взгляд выделенного объекта на 45°, без выделения — взгляд следующего ставящегося. У блоков R остаётся поворотом блока: клавиши работают по инструменту;
  - Esc снимает выделение.
- **Список «На карте»** под свойствами: все объекты, клик выделяет и переносит к нему центр камеры.
- **Содержимое контейнера** правится в свойствах: список предметов с количеством и «Добавить предмет» — тот же поиск по каталогу. Каждое изменение — `updateObject`. Компоненты списка — по образцу снаряжения монстра, где подойдут.
- **Телефон:** клик выделяет, а перетаскивание заменяет «Перенести» в свойствах, после которого касание клетки переносит объект. На телефоне одним пальцем крутят камеру, и отличить начало перетаскивания объекта от жеста камеры труднее, чем мышью.

### Как выглядят объекты

Выбрано пользователем 2026-10-20: существо — стоячая карточка.

- **Существо** — карточка с миниатюрой монстра или персонажа. Сначала она поворачивалась к камере; после закрытия плана (2026-10-20, по просьбе пользователя) это объёмный жетон в подставке с картинкой с обеих сторон, лицом по взгляду существа. Высота — по росту размера (`rules/creature.ts`). На полу — подставка размером с место существа и стрелка взгляда. Без картинки — силуэт и первая буква имени. Заглушка (скрыт или удалён) — серая карточка со знаком вопроса.
- **Старт** — плитка на полу с номером и стрелкой взгляда.
- **Контейнер** — простая 3D-фигура по виду (сундук, ящик, бочка, мешок) в одну клетку.
- **Предмет на полу** — маленькая карточка с миниатюрой предмета, лежащая на полу.
- Имя — подсказкой при наведении во всех инструментах. Выделенный объект обведён.

### Нейросеть (MCP)

Выбрано пользователем 2026-10-20: токен получает чтение каталога.

- **API-токен может искать** монстров и предметы (свои и опубликованные) и своих НПС: только поиск по названию и чтение по id, без записи. Остальное в каталоге и персонажах токену по-прежнему закрыто.
- **Новый инструмент MCP** `find_catalog` поверх `GET /map-catalog`: вид (монстр, предмет, НПС) и строка поиска. Возвращает id, имя, размер и роль монстра или категорию предмета.
- `apply_ops` знает операции объектов. `map_summary` перечисляет объекты с номерами, видами, клетками и предупреждениями («в стене», «в воздухе», «заглушка»). Объекты, стоящие на уровне среза, перечислены под ним (номер, подпись, клетка, предупреждения): символами на сетке они заслонили бы блоки. `block_guide` объясняет объекты.

## Не берём сейчас

- **Скрытые объекты и туман войны.** Поле `hidden` заложено, но ни редактор, ни чтение им не пользуются (roadmap, «После первой партии»).
- **Существа как препятствие для пути** и правила стойки на объектах: остаются в «Путь, потом» в [map.md](../map.md).
- **Двери, ловушки, источники света** — те же объекты, но позже.
- **Бросок ХП экземпляра монстра** и вообще состояние экземпляра — это сцена, блок 4.
- **Привязка точки старта к персонажу** — в лобби.
- **Копирование объектов и выделение рамкой** — вместе с выделением блоков ([map.md](../map.md), этап 5, «Отложено»).
