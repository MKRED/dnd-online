# Персонажи: просмотр и доступ по ссылке

Живой план. Сейчас у персонажа есть только форма редактирования, и видит его лишь автор. Здесь — страница просмотра персонажа (как карточка предмета) и общий доступ по постоянной ссылке, как в Google Таблицах.

## Что делаем

- **Страница просмотра** `/characters/:id`: лист персонажа только для чтения — картинки, характеристики с модификаторами, боевые параметры, владения, снаряжение, личность. Редактирование остаётся на `/characters/:id/edit`.
- **Доступ к персонажу** выбирает автор, два режима:
  - «Только я» — по умолчанию, как сейчас;
  - «Все, у кого есть ссылка» — только просмотр.
- **Ссылка постоянная**: это адрес страницы просмотра. Закрыл доступ — по той же ссылке персонаж больше не открывается, открыл снова — она снова работает.
- **Редактирует, удаляет и меняет доступ только автор.** У остальных на странице просмотра нет ни кнопок, ни запросов, которые бы это позволили: сервер проверяет автора, как и сейчас.

## Принятые решения

### Ссылка — это адрес персонажа, а не отдельный токен

- Как в Google Таблицах: ссылка одна и та же при любом доступе, режим доступа решает, пустят ли по ней.
- id персонажа — UUID v4, угадать его нельзя, так что отдельный секрет в ссылке ничего не добавляет.
- Цена решения: нельзя «перевыпустить» ссылку, чтобы отрезать тех, у кого она уже есть, и оставить доступ новым. Можно только закрыть доступ всем. Для игры с друзьями этого хватает; если понадобится — добавим токен позже (см. открытые вопросы).

### Хранение

- Колонка `characters.link_access` — `varchar(20)`, `'private'` или `'link'`, по умолчанию `'private'`. Не `boolean`: позже может появиться доступ для участников кампании.
- Нужна миграция `0019`. **Локальная база — это прод**, поэтому миграцию применяем только с согласия пользователя.
- Существующие персонажи остаются приватными.

### Сервер

- `GET /characters/:id` отдаёт персонажа автору или любому вошедшему, если доступ `'link'`. Приватный чужой персонаж неотличим от несуществующего — 404 «Персонаж не найден», как сейчас.
- В ответе добавляются `linkAccess` и `authorNickname`: на странице просмотра чужого персонажа видно, чей он.
- `PUT`, `PATCH`, `DELETE` персонажа и правки галереи не меняются: они уже фильтруют по автору.
- Смена доступа — отдельный `PUT /characters/:id/access { linkAccess }`, а не поле общей формы: доступ меняется из диалога «Поделиться» сразу, без сохранения листа.
- Галерея: список картинок и их файлы (`GET …/images`, `GET …/images/:imageId/file`) читатель по ссылке получает так же, как автор. Нужна проверка «может смотреть» рядом с `assertOwnedCharacter`. Загрузка, удаление, основная картинка и вырез миниатюры — только автор.
- Кеш картинок остаётся `private`: файлы хранит только браузер зрителя, общие кеши — нет. Закрытие доступа не стирает то, что зритель уже загрузил, — это нормально, как и с любой ссылкой.
- Список `GET /characters` по-прежнему только свои: «Доступные мне» в этот план не входят (см. открытые вопросы).

### Страница просмотра

```
← К персонажам
┌──────────┐  Торин Дубощит                    [Поделиться] [Редактировать] [⋯]
│ картинка │  Дварф · Солдат · Законно-добрый
│          │  [Воин 3] [Плут 1]               ХП 24/31 (+5)  КД 16  Скорость 25
└──────────┘
[мин][мин][мин]  ← галерея, только просмотр (лайтбокс есть)

Характеристики     СИЛ 16 (+3)  ЛОВ 12 (+1)  ТЕЛ 14 (+2)  ...
Спасброски / Навыки (владение отмечено, бонус посчитан)
Боевые параметры   Инициатива +1 · Бонус мастерства +2 · Кость хитов к10 · ...
Владения, атаки, заклинания, снаряжение и деньги, умения, личность — пустые разделы не показываем.
```

- Разделы и подписи — те же, что в форме, и в том же порядке: кто привык к форме, найдёт поле на том же месте. Считаемое (модификаторы, инициатива, бонусы навыков) берём из тех же функций, что форма (`abilityMath.ts`), а не пишем заново.
- У чужого персонажа вместо кнопок автора — строка «Автор: <ник> · только просмотр».
- «Удалить» прячется в меню `⋯`, чтобы не стоять рядом с частым «Редактировать»; подтверждение — как сейчас.
- Узкий экран: картинка над именем, кнопки переносятся, характеристики — сетка по 3 в ряд.

### Переходы

- В списке «Мои персонажи» карточка (имя и картинка) открывает просмотр. Кнопки «Редактировать» и «Удалить» в карточке остаются: правка — частое действие, лишний клик через просмотр ей не нужен.
- После сохранения формы — на страницу просмотра этого персонажа, как у предметов. Сейчас форма уводит в список с подсветкой: подсветку убираем, она больше не нужна.
- После создания — как сейчас, на редактирование с подсказкой «добавьте картинки».
- «Назад» со страницы редактирования ведёт на просмотр, со страницы просмотра — в список.

### Диалог «Поделиться»

```
┌ Доступ к персонажу ───────────────────────────┐
│ ( ) Только я                                  │
│     Персонажа видите только вы.               │
│ (•) Все, у кого есть ссылка                   │
│     Могут смотреть, но не изменять.           │
│                                               │
│ [https://dnd.aoshi.ru/characters/3f2…] [Копировать] │
│                                     [Готово] │
└───────────────────────────────────────────────┘
```

- Режим сохраняется сразу при выборе (с индикатором и ошибкой в диалоге, если не вышло), отдельной кнопки «Сохранить» нет — как в Google.
- Поле ссылки и «Копировать» видны всегда; при «Только я» под ними пометка «Сейчас по ссылке откроется только у вас». После копирования кнопка на пару секунд пишет «Скопировано».
- В списке у персонажа с открытым доступом — значок-бейдж «По ссылке», чтобы автор помнил, что лист видят другие.

### Вход по ссылке

- Страница просмотра остаётся за входом (см. открытые вопросы про анонимов).
- Сейчас `RequireAuth` отправляет на `/login` и забывает, куда шёл человек: друг по ссылке после входа попадёт на главную. Чиним: адрес запоминается, после входа (паролем, регистрацией и через lolka) возвращаемся на него. Разрешаем только внутренние пути, чтобы вход нельзя было использовать как открытый редирект.

### Где будет в коде

- `apps/server/src/database/schema/characters.ts`, миграция `0019`.
- `apps/server/src/characters/` — проверка доступа на чтение, `PUT :id/access`, `authorNickname` в ответе.
- `apps/server/src/character-images/character-image-access.ts` — проверка «может смотреть» для списка и файлов.
- `packages/shared/src/character.ts` — `CHARACTER_LINK_ACCESS`, поля `linkAccess` и `authorNickname` у `Character`.
- `apps/web/src/pages/CharacterViewPage.tsx` и `apps/web/src/features/characters/CharacterSheet/` — лист только для чтения по разделам.
- `apps/web/src/features/characters/ShareDialog/` — диалог доступа.
- `CharacterGallery` — режим только для просмотра (без загрузки, меню картинки и выреза).
- `apps/web/src/features/auth/` и страницы входа — возврат на исходный адрес.

## Решено с пользователем 2026-10-15

- **Смотреть можно только после входа.** Анонимного доступа по ссылке нет: играем с друзьями, аккаунт есть у всех. Ссылка при этом та же, так что добавить его позже можно, ничего не ломая.
- **Список «Доступные мне» откладываем** до кампаний: там мастеру нужен список персонажей партии, и он закроет ту же задачу.
- **Перевыпуска ссылки нет:** чтобы отрезать доступ, автор закрывает его всем.
