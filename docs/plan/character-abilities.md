# Способности и ячейки заклинаний у персонажа

Живой план. Отмечаем этапы по мере готовности. Блок 1 общего плана [roadmap.md](roadmap.md).

## Что делаем

- **Способности на листе.** Игрок добавляет персонажу способности из каталога ([done/abilities.md](done/abilities.md)): умения и заклинания. Лист показывает их двумя блоками, «Умения» и «Заклинания», как обычный лист D&D.
- **Ячейки заклинаний.** Игрок сам вводит, сколько ячеек каждого круга у персонажа, и отмечает на листе потраченные. Приложение ячейки не считает и способностями их не тратит: это придёт с боем на карте.

Что уже есть в коде:

- В базе у персонажа есть колонка `spell_slots` (по кругам 1–9: `total` и `expended`), DTO её проверяет (`expended ≤ total`). В интерфейсе её нет: форма её не отправляет, лист не показывает.
- Текстовые поля `spellsKnown`, `features` и `attacks` тоже есть только в API, в интерфейсе их нет. Они остаются как есть (решено с пользователем 2026-10-19). Новые способности хранятся отдельно, данные не переносим.
- `sheetTotals` уже принимает не весь `Character`, а только `speed`, `armorClass`, `abilityScores` и `effects`. Поэтому отдельная «форма существа» в этом блоке не нужна. Монстр в блоке 2 даст те же поля, и тогда тип вынесем под общим именем.

## Решения

Согласованы с пользователем 2026-10-19.

### Лист: «Умения» и «Заклинания»

```
┌ Умения ───────────────────── [+ Способность] ┐
│ Действие                                      │
│   Второе дыхание     бонусное · 1/кор. отдых  │
│ Реакция                                       │
│   Парирование        реакция                  │
├ Заклинания ─────────────────── [Долгий отдых] ┤
│ Заговоры                                      │
│   Огненный снаряд    действие                 │
│ 1 круг   ● ● ○ ○                              │
│   ● Щит              реакция                  │
│   ○ Волшебная стрела действие                 │
│ 2 круг   ● ●                                  │
│   ● Туманный шаг     бонусное                 │
└───────────────────────────────────────────────┘
 ● у заклинания — подготовлено; ● ○ у круга — ячейки: полная и потраченная
```

- **«Умения»** — способности категории «Базовая», сгруппированы по активации в порядке `ABILITY_ACTIVATION_KINDS`: Действие, Бонусное действие, Реакция, Без действия, Вместо атаки, Долгое применение. Пустые группы не показываются.
- **«Заклинания»** — способности категории «Заклинание», по кругам: Заговоры, затем 1–9 круг. Ячейки круга стоят в его заголовке, рядом с тем, на что они тратятся. Круг с ячейками, но без заклинаний, всё равно показывается: ячейки бывают и до того, как заклинания добавлены.
- **Строка способности:** название — ссылка на карточку (`/abilities/:id`), справа — активация и затраты короткой строкой (подписи из `abilityUsageLabels`). У заклинания 1 круга и выше слева отметка «подготовлено». У заговора её нет: заговоры не готовят.
- **Порядок разделов листа:** после характеристик, перед владениями.
- **Пустой раздел.** Автор видит «Способностей пока нет» и кнопку «+ Способность». Зритель по ссылке пустой раздел не видит. Блок «Заклинания» есть, если у персонажа есть заклинания или ячейки.
- **Удаление** — крестик в строке у автора, без подтверждения, как у эффектов: вернуть способность можно парой кликов.

### Ячейки заклинаний

- **Число ячеек задаётся в форме:** раздел «Ячейки заклинаний», девять маленьких полей по кругам, по умолчанию 0. Подпись поясняет, что число вводится вручную по таблице класса.
- **Тратятся на листе.** Кружки в заголовке круга: полный — ячейка есть, пустой — потрачена. Клик по полному тратит ячейку, клик по пустому возвращает её. Сохраняется сразу, как ХП. Тратятся всегда крайние справа: важно, сколько потрачено, а не какая именно.
- **«Долгий отдых»** в заголовке «Заклинаний» возвращает все ячейки. Подтверждение не нужно: вернуть потраченные можно кликами. Кнопку не показываем, когда потраченных ячеек нет. Правило книги — ячейки возвращаются после долгого отдыха ([dnd/ability-usage.md](../dnd/ability-usage.md), «Spell slot»).
- **Магия договора колдуна** (ячейки возвращаются и после короткого отдыха) пока не отделена от обычных ячеек: открытый вопрос.
- **Форма и потраченные.** Форма отправляет полный `spellSlots`, а `expended` берёт из загруженного персонажа и уменьшает до нового `total`, если число ячеек урезали. Так правка формы не сбрасывает потраченное.
- **Тратит только автор**, зритель по ссылке видит кружки без действий.

### Хранение способностей

Ссылка на запись каталога, как у эффектов ([done/character-effects.md](done/character-effects.md)):

```
character_abilities
  id            uuid PK
  character_id  uuid → characters.id  ON DELETE CASCADE
  ability_id    uuid → abilities.id   ON DELETE SET NULL   -- null: «Способность удалена автором»
  prepared      boolean NOT NULL DEFAULT false             -- смысл есть только у заклинания 1+ круга
  added_at      timestamptz                                -- порядок внутри группы
  UNIQUE (character_id, ability_id)
  INDEX (ability_id)
```

- **Одна способность — один раз:** повтор — 409 «Способность уже добавлена».
- **Откуда способность** (класс, вид, черта) пока не храним. Это понадобится вместе с ростом от уровня класса ([done/abilities.md](done/abilities.md), «Открытые вопросы»), тогда и добавим колонку.
- **Скрытая и удалённая способность** — как эффект: строка «Способность скрыта автором» или «Способность удалена автором». Её можно только убрать. Такие строки стоят в «Умениях» отдельной группой «Недоступны»: категория скрытой карточки не видна.
- **Заряды** («1 раз за короткий отдых») показываются из затрат способности, но не считаются: как и где хранить заряды, решаем отдельной задачей ([roadmap.md](roadmap.md), «После первой партии»).
- **Заклинание перестало быть заклинанием** (автор сменил категорию): `prepared` остаётся в базе, но лист его не показывает.

### API

Менять может только автор персонажа, отдельно от формы:

- `GET /characters/:id` и список отдают `abilities`: строки с карточкой (название, категория, круг, активация, затраты, миниатюра) или `ability: null` и `state: 'hidden' | 'deleted'`, как `effects`.
- `POST /characters/:id/abilities` — `{ abilityId }`. Способность должна быть видна автору персонажа, иначе — 400 «Способность не найдена».
- `PATCH /characters/:id/abilities/:entryId` — `{ prepared }`. У не-заклинания и у заговора — 400 «Подготовить можно только заклинание 1 круга и выше».
- `DELETE /characters/:id/abilities/:entryId`.
- `PATCH /characters/:id` получает `spellSlotsExpended`: потрачено по кругам, `{ "1": 2 }`. Больше, чем ячеек круга, — 400. «Долгий отдых» — нули по всем кругам.

### Код

- Сервер: `apps/server/src/characters/abilities/`, рядом с `effects/` и `inventory/`.
- Веб: `apps/web/src/features/characters/Abilities/`, как `Effects/`. Имя `AbilitiesView` в листе уже занято характеристиками (ability scores), новый раздел его не трогает.
- Список способностей и окно добавления принимают строки и обработчики, а не `Character`, чтобы монстр в блоке 2 взял их без копирования.

## Этапы

- [ ] **1. Ячейки: сервер.** `spellSlotsExpended` в `PATCH /characters/:id`, проверка «не больше ячеек круга». Тесты e2e: потратить и вернуть, больше ячеек — 400, круг без ячеек — 400, аноним 401, чужой 404, по ссылке — не меняет; форма (PUT) сохраняет потраченное. Мутационная проверка предела.
- [ ] **2. Ячейки: интерфейс.** Раздел «Ячейки заклинаний» в форме; блок «Заклинания» на листе пока только с ячейками; кружки, «Долгий отдых». Тесты: компонентные (трата и возврат, отдых, зритель без действий, форма урезала ячейки — потраченное уменьшилось). Проверка в браузере: обе схемы, 390 px.
- [ ] **3. Способности: сервер.** Таблица и миграция, маршруты, `abilities` в листе и списке. Тесты e2e по образцу `character-effects.e2e-spec.ts`: добавить, повтор — 409, подготовить, подготовить не-заклинание и заговор — 400, убрать; неверная, несуществующая и чужая скрытая способность — 400; аноним 401, чужой 404, по ссылке — видит, но не меняет; скрытая после добавления — без карточки, удалённая — «удалена». Мутационная проверка правила скрытия.
- [ ] **4. Способности: лист.** «Умения» по активации, «Заклинания» по кругам с ячейками, отметка «подготовлено», окно «+ Способность» с поиском по своим и каталогу (добавленные видны, но выбрать их нельзя), недоступные строки, пустые состояния. Тесты: компонентные (группы, подготовка, удаление, окно с уже добавленной и ошибкой 409, зритель). Проверка в браузере: обе схемы, 390 px, длинные названия.
- [ ] **5. Прод.** По просьбе пользователя: деплой, проверка на проде тестовым аккаунтом.

## Открытые вопросы

- Магия договора колдуна: отдельный ряд ячеек, которые возвращаются после короткого отдыха, или пока хватит одного набора.
- Сортировка внутри группы: по порядку добавления (сейчас) или по названию.
