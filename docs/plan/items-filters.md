# Предметы: простые категории и фильтры каталога

Продолжение [items.md](items.md): основа (общие поля, картинка, каталог с авторами) уже в проде. Здесь три категории без своих полей и фильтры в списке предметов.

## Что делаем

- Три новые категории: **«Еда и напитки»**, **«Материалы»**, **«Сюжетный»**. Своих полей у них нет: у предмета только общие поля, как у «Базового».
- Категорию можно выбрать в форме и при создании, и при правке.
- Над списком предметов, на обеих вкладках («Мои» и «Каталог»), появляются:
  - фильтр по категории;
  - поиск по названию;
  - фильтр по редкости;
  - сортировка.

## Принятые решения

### Категории без своих полей

- **Ключи:**
  - `food` — «Еда и напитки»;
  - `material` — «Материалы»;
  - `quest` — «Сюжетный».

  `details` у них пустой объект, как у `basic`; сервер проверяет это тем же правилом.

- **Миграция не нужна.** Колонка `category` — `varchar(30)` без перечня в базе, допустимые значения проверяет DTO.
- **Без полей сознательно.**
  - «Порции» у еды, «нельзя продать/выбросить» у сюжетного и связь материалов с ремеслом имеют смысл только в инвентаре персонажа и в игре, а их пока нет (см. «Позже» в [items.md](items.md)).
  - На этапе 1 проверяем по правилам 2024, что сказано о рационах и еде. Найденное записываем в [docs/dnd/items.md](../dnd/items.md) с источником и датой, даже если в коде оно пока не используется: так видно, почему полей нет.
- **Смена категории при правке разрешена.** Сейчас при ней ничего не теряется. Когда появятся категории со своими полями, смена будет сбрасывать `details`, и форма должна об этом предупреждать. Решаем на их этапе.
- **В форме у поля «Категория» подсказка меняется вместе с выбором.** Например: «Пища, напитки, рационы» или «Ключи, письма, артефакты сюжета — то, что важно для истории». Так понятно, что куда класть.
- **Значок категории на карточке уже есть** (`ItemBadges`), он подхватит новые названия сам.

### Фильтры на клиенте

- **Фильтруем и сортируем в браузере, по уже загруженному списку.** API сейчас отдаёт всю вкладку целиком, а предметов в каталоге десятки. Поэтому ответ мгновенный, без запросов и без новых параметров API.
- Когда каталог вырастет (готовые предметы из книги — сотни), перенесём фильтры на сервер с постраничной выдачей. Параметры адреса останутся теми же и просто уйдут в запрос.
- **Состояние фильтров — в адресе страницы**, как уже сделано с вкладкой: `?tab=catalog&cat=food,material&rarity=magic&q=верёв&sort=name`.
  - «Назад» с карточки предмета возвращает тот же отфильтрованный список, ссылкой можно поделиться.
  - Ввод в поиск меняет адрес через `replace`, чтобы не засорять историю.
  - В `localStorage` фильтры не сохраняем: открыл раздел заново — видишь всё.
- **Фильтры общие для обеих вкладок:** при переключении «Мои» ↔ «Каталог» они остаются.
- **Значения по умолчанию в адрес не пишем.** Чистый `/items` — это все категории, любая редкость, сначала новые.

### Как выглядит

```
Предметы                                        [Создать предмет]
[ Мои | Каталог ]                                  [Сетка|Список]

[🔍 Поиск по названию...........................................]
(Все) (Базовый 4) (Еда и напитки 2) (Материалы 0) (Сюжетный 1)
[Редкость: любая ▾]                       [Сортировка: новые ▾]

┌────┐ ┌────┐ ┌────┐
│    │ │    │ │    │   ...
└────┘ └────┘ └────┘
```

- **Категории — ряд чипов** (выбрано с пользователем).
  - Можно отметить несколько. «Все» снимает выбор, и «Все» горит, когда не выбрано ничего.
  - Рядом с названием — сколько таких предметов на текущей вкладке, с учётом поиска и редкости, но не самой категории. Так видно, куда стоит нажать.
  - Пустые категории не прячем: ряд не прыгает.
  - На узком экране чипы переносятся. Когда категорий станет около 15, ряд свернём в выпадающий список с несколькими значениями.
- **Поиск** — строка во всю ширину с крестиком очистки.
  - Ищет по подстроке в названии, без учёта регистра, «ё» = «е».
  - Описание не ищем: длинные описания дают ложные совпадения.
- **Редкость** — выпадающий список:
  - «Любая»;
  - «Без редкости»;
  - «Магические (любая редкость)»;
  - затем каждая редкость по отдельности.
- **Сортировка** — выпадающий список:
  - «Сначала новые» (как сейчас: по дате изменения);
  - «По названию» (А→Я, `localeCompare` с русской локалью);
  - «Сначала лёгкие»;
  - «Сначала дешёвые».

  При сортировке по цене цена переводится в медные монеты; предметы без цены идут в конец. **Курс монет проверить по правилам 2024** и записать в [docs/dnd/items.md](../dnd/items.md): ЭМ и ПМ там уже помечены как непроверенные.

- **На узком экране** редкость и сортировка стоят в одну строку, каждая на половину ширины.
- **Ничего не нашлось:** «Под фильтры ничего не подошло» и кнопка «Сбросить фильтры». Этот текст отличается от пустой вкладки, где сейчас «У вас пока нет предметов…». Когда вкладка пустая совсем, фильтры не показываем.
- **Хоткей** `/` ставит курсор в поиск. Мелочь, но список будет длинным.

### Где в коде

- `features/items/itemFilters/` — чистые функции, все с юнит-тестами:
  - `filterItems`;
  - `sortItems`;
  - подсчёт по категориям;
  - разбор и запись параметров адреса (неизвестные значения в адресе молча отбрасываем).
- `features/items/ItemFilters/` — компонент панели фильтров.
- `ItemsPage` только связывает адрес, загруженный список и панель.
